# Sofivita — сайт для Софьи и Витали

Полный проект для GitHub Pages. Это готовый статический сайт: сервер, база данных,
Node.js, Python и сборка для его работы не нужны. Все фотографии, шрифты,
изображения поезда и рельсов находятся в архиве.

## Быстрый запуск на GitHub Pages

1. Распакуй `sofivita-github-pages.zip`.
2. Создай на GitHub новый репозиторий, например `sofivita`, с основной веткой `main`.
3. Загрузи **содержимое распакованного архива** в корень репозитория и сохрани commit.
   В корне сразу должны находиться `index.html`, `assets`, `scripts`, `.github` и `.nojekyll`.
   Сам ZIP загружать вместо файлов сайта не нужно: GitHub не распаковывает его.
4. Открой **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Открой **Actions → Publish Sofivita to GitHub Pages → Run workflow → main → Run workflow**.
   Если после включения Pages ты ещё раз загрузил файлы в `main`, публикация запустится автоматически.
6. После успешного выполнения ссылка на сайт появится в **Settings → Pages**.

Обычный адрес проекта имеет вид `https://ТВОЙ-ЛОГИН.github.io/sofivita/`.
Имя репозитория можно выбрать другое: ссылки на фотографии и шрифты относительные.

Если работаешь с Android, настройки удобнее открывать в браузере с режимом «Версия для ПК».
При загрузке необходимо сохранить папки и их содержимое, включая скрытую папку `.github`.
Если файловый выбор на телефоне не умеет загружать папки, используй Git, как описано ниже.

## Публикация из ветки без собственного workflow

Готовый `index.html` расположен в корне, поэтому можно выбрать и стандартный вариант:

1. Удали из своей копии репозитория `.github/workflows/pages.yml`, чтобы не было двух публикаций.
2. В **Settings → Pages** выбери **Deploy from a branch → main → /(root) → Save**.

Файл `.nojekyll` уже приложен. Он отключает обработку сайта Jekyll.

## Загрузка через Git

Выполняй из распакованного каталога проекта. Сначала создай пустой репозиторий на GitHub.
Укажи свои имя, email и URL репозитория вместо примеров:

```bash
git init -b main
git config user.name "Vitalya"
git config user.email "YOUR_EMAIL"
git add .
git commit -m "Publish Sofivita website"
git remote add origin https://github.com/YOUR_LOGIN/sofivita.git
git push -u origin main
```

При запросе входа используй настроенный у тебя способ авторизации GitHub.
После загрузки включи Pages по инструкции выше.

## Что находится в проекте

| Путь | Назначение |
| --- | --- |
| `index.html` | Весь интерфейс, оформление, анимации и логика сайта |
| `assets/sofia-vitalya.jpg` | Совместная фотография на главной |
| `assets/memory-1.jpg` … `memory-7.jpg` | Семь фотографий для слайдшоу |
| `assets/train/` | Готовые изображения поезда и рельсов, лицензия Kenney |
| `assets/fonts/` | Локальные Manrope и Caveat, их CSS и лицензии |
| `.github/workflows/pages.yml` | Публикация при изменении ветки `main` и ручной запуск |
| `scripts/verify-site.mjs` | Проверка ссылок на файлы и синтаксиса JavaScript |
| `scripts/render-train-assets.py` | Повторная отрисовка поезда из оригинальных 3D-моделей |
| `source-assets/kenney-train-kit/` | Исходные модели Kenney, цветовая карта и лицензия |
| `requirements-renderer.txt` | Зависимости только для повторного создания изображений поезда |
| `docs/CNAME.example` | Пример файла для собственного домена |

Через GitHub Actions публикуются только `index.html`, `assets`, `.nojekyll` и, если добавлен, `CNAME`.

## Что уже работает

- При открытии едет поезд с двумя вагонами; можно сразу перейти к приглашению.
- Во время загрузки показываются семь фотографий в карточке Polaroid.
- На главной — приглашение на 26 октября, совместная фотография, эффекты и ночная тема.
- Кнопка «Я подумаю…» плавно убегает и использует заданные тобой фразы.
- «Да» открывает сообщение и кнопку перехода к `@out_casual` с готовым текстом.
- Основной поезд ждёт **26 октября 2026 года, 07:05 по Москве**.
- С **07:05 до 12:10** он движется по маршруту; отсчёт показывает время до прибытия.
- С **12:10** отображаются «Этот день наступил» и станция «Мы рядом».

Время задано с явным смещением UTC+3 и одинаково работает независимо от часового пояса телефона.
Состояние рассчитывается по часам устройства посетителя. Страница сама обновляется после смены состояния.
Поезд в загрузке показывает отдельную короткую анимацию и не зависит от реального ожидания отправления.

## Что менять

Открой `index.html` в редакторе и найди нужный текст. Перед редактированием сделай копию.

- Расписание — блок `<script id="trip-schedule">`: отправление `2026-10-26T07:05:00+03:00`, путь `(5*60+5)*60000`.
- Также обнови видимую строку расписания `26 октября · 07:05 → 12:10 МСК · 5 ч 5 мин`, если изменишь время поездки.
- Telegram — ссылка `https://t.me/out_casual?text=...` в кнопке `notify-vitaly`.
- Фотографии — замени файлы в `assets`, сохранив имена. Слайдшоу использует вертикальные фотографии.
- Внешний вид — правила внутри `<style>` в `index.html`.

## Проверка и просмотр на компьютере

```bash
node scripts/verify-site.mjs
python3 -m http.server 8000
```

Открой `http://localhost:8000/`. Проверка и локальный сервер необязательны для загрузки на GitHub Pages.

Только если понадобится заново отрисовать поезд:

```bash
python3 -m pip install -r requirements-renderer.txt
python3 scripts/render-train-assets.py
```

## Собственный домен sofivita.ru

По умолчанию проект подготовлен для адреса `github.io`.
Чтобы подключить `sofivita.ru`, открой **Settings → Pages → Custom domain**,
добавь свой домен и настрой DNS у регистратора по актуальной инструкции GitHub.
После настройки можно скопировать `docs/CNAME.example` в корень под именем `CNAME`.
Этот файл — одна строка с доменом. Пример не включён как активный домен заранее.

## Общий счётчик ссор

Число для всех посетителей хранится в `assets/data/quarrels.json` в поле `count`.
Начальное значение — 0. Чтобы изменить его, отредактируй это число в репозитории
и сохрани commit: после публикации Pages все устройства получат одно значение.
Счётчик проверяет обновления раз в минуту и при возвращении на вкладку.
Локальное хранилище телефона не используется. При ошибке число не сбрасывается.
Публикация идёт существующим способом из ветки `main`, папка `/ (root)`.
